# 관광 코스·15분·저장 경계

기준일: 2026-11-13. 최신 사용자 요청과 [ROAD_ESCAPE_sdk.md](ROAD_ESCAPE_sdk.md)를 바탕으로 구현한 관광 흐름입니다. 기존 3경유지 Mock 테스트는 보존하고, 별도의 수원 5챕터 검증 패키지와 실제 Pleos SDK 어댑터를 추가했습니다. **기능 구현과 SDK의 실제 수신·인증 성공은 구분합니다.** 최신 UI 통합본의 최종 빌드·기기 검증 결과는 [검증 기록](verification.md)에 따로 기록합니다.

## 두 패키지와 입력 모드

| 구분 | 기존 테스트 | 신규 관광 검증 코스 |
| --- | --- | --- |
| 패키지 ID | `demo_package` | `suwon_tour_preview` |
| assets | `demo_package.json` | `suwon_tour_package.json` |
| 경유지 | 가상 경유지 3개 | 수원 관광지 5곳 |
| 관광 조건 | 적용하지 않음 | 각 경유지에 15분·위치 재인증 적용 |
| 문제 | 기본 자물쇠 3종 | 같은 입력 체계를 사용한 임시 연동 문제 5개 |

관광지 순서만 확정됐고 각 장소의 실제 역사·관찰 문제와 줄거리는 제작 전입니다. 임시 정답이나 단서 보상을 관광지 방문·현장 관찰 성공 증거로 사용하지 않습니다.

- `MOCK`: debug에서만 선택합니다. 모의 위치·주차와 명시적인 15분 경과 시연으로 흐름을 확인합니다.
- `LIVE`: 새 Fused 위치, 주차·정지, CarUx 제한을 실제 어댑터에서 받습니다. 미지원·오류·권한 거절을 MOCK으로 자동 대체하지 않습니다.
- release에는 모의 입력과 개발 패널이 없으며 실제 모드를 사용합니다. 과거 `MOCK` 원장을 `LIVE` 기록으로 바꿔 읽지 않습니다.

## 관광지 대표점과 현장 검증

현재 [TourCatalog.kt](../app/src/main/java/com/example/roadescape/game/TourCatalog.kt)에 다음 공개 대표점을 초기값으로 넣었습니다. **주차장 좌표가 아니며, 현장에서 실측하거나 합법적인 주차 접근성을 확인한 결과가 아닙니다.** 사용자가 앱에서 좌표·반경을 임의로 바꾸는 기능은 없습니다.

| 순서 | 관광지 | 위도, 경도 | 공개 출처·확인 범위 |
| --- | --- | --- | --- |
| CH.1 | 화성행궁 | `37.281791, 127.013251` | 수원시 2019 관광 가이드 PDF 24쪽 |
| CH.2 | 화홍문 | `37.287456, 127.017955` | 같은 PDF 19쪽 |
| CH.3 | 만석공원·만석거 | `37.301607, 127.001058` | 같은 PDF 52쪽, 실제 방문 구역·최종 인증 중심 미확정 |
| CH.4 | 수원광교박물관 | `37.296351, 127.051421` | 공공데이터포털 공공시설 자료의 2026-05-19 수정본 후보 |
| CH.5 | 광교호수공원 | `37.281651, 127.070650` | 같은 PDF 45쪽, 실제 방문 구역·최종 인증 중심 미확정 |

가이드 쪽수는 **1부터 세는 PDF 페이지**입니다. 출처는 [수원시 관광 가이드 원문](https://www.suwon.go.kr/webcontent/ckeditor/2019/1/28/22c61a9a-2220-4abc-a683-ea4bd025f901.pdf), [공공데이터포털 시설 자료](https://www.data.go.kr/data/15017323/standard.do)이며, 코드에도 URL을 기록했습니다. 공개 대표점이 실제 방문 구역과 맞는지, 500m 범위에서 합법적으로 주차하고 관광할 수 있는지는 **다섯 구간 모두 현장 확인이 필요합니다.**

모든 반경은 **500m 임시값**입니다. 정확한 대표점이 `null`인 경우 LIVE 위치 인증과 해당 목적지 안내 요청을 허용하지 않습니다. 거리 계산은 내부 정책에만 사용하며 사용자 화면에 미터·킬로미터 거리 숫자를 표시하지 않습니다.

## 시작과 복귀 판정

1. 로비에서 **수원 관광 코스 · 5챕터**를 엽니다.
2. **실제 여행 시작** 또는 debug의 **시연 데이터로 시작**을 선택합니다. 기존 진행이 있으면 새 게임 확인을 거칩니다.
3. 현재 챕터의 반경 내 새 위치와 foreground·P·정지·CarUx 게임 허용을 확인합니다.
4. **관광 시작**을 누릅니다. `TourStartRecord`를 저장한 뒤에만 저장된 시작 기록을 화면에 표시합니다. 같은 세션·챕터·모드에서 다시 눌러도 최초 시작 시각을 다시 쓰지 않습니다.
5. 자유롭게 관광합니다. 앱 프로세스나 차량 전원이 꺼진 동안 타이머를 계속 실행하지 않습니다.
6. 복귀 후 앱을 열어 **현재 위치와 안전 상태를 새로 확인**합니다. 시작 때의 좌표, NaviHelper 도착 이벤트, 시동 OFF/ON만으로 인증하지 않습니다.
7. 저장한 시작부터 15분 이상, 최신 위치가 같은 관광지 반경 내, 안전한 게임 이용 상태, 이전 챕터 완료가 모두 맞아야 퍼즐을 엽니다.
8. 퍼즐을 해결하거나 확인 후 건너뛰면 게임 진행·단서를 저장하고 다음 챕터로 이동합니다. 다음 장소에는 별도의 관광 시작 기록이 필요합니다.

주행·UNKNOWN·백그라운드·UX 제한·위치 만료가 발생하면 퍼즐과 민감한 내용을 가리고 변경 명령을 막습니다. 이미 정상 저장을 마친 결과는 취소하지 않습니다. 이전 세션·퍼즐·입력 모드의 늦은 명령도 거절합니다.

### debug로 5챕터 시연

각 챕터에서 **PARKED → 도착 위치 시연 → 관광 시작 → 저장 완료 확인 → 15분 경과 시연 → 퍼즐 열기**를 진행합니다. 해결·건너뛰기 뒤 다음 챕터에서도 같은 절차를 반복합니다. **15분 경과 시연은 실제 시간을 앞당기거나 실제 관광을 인증하는 기능이 아닙니다.** 해당 MOCK 기록에 debug 우회 표시를 저장합니다. LIVE에서는 이 명령을 허용하지 않습니다.

배경으로 나갔다 돌아오면 모의 주차·위치도 무효화됩니다. PARKED와 도착 위치를 다시 시연한 뒤 진행해야 합니다. MOCK의 가상 위치 갱신은 실제 FusedLocation 콜백 관측으로 보고하지 않습니다.

## 위치 품질과 현재 LIVE 보류 사유

[TourPolicy.kt](../app/src/main/java/com/example/roadescape/game/TourPolicy.kt)의 기본 검증값은 아래와 같습니다.

| 항목 | 현재 앱 정책 |
| --- | --- |
| 최소 관광 시간 | **15분 고정** |
| 인증 반경 | 500m 임시값 |
| 정책 계층의 위치 최대 나이 | 30초 |
| 위치 정확도 상한 | 100m |
| 정책 계층의 미래 위치 시각 허용 | 5초 |
| 같은 부팅의 wall/monotonic 차이 허용 | 120초 |
| 재부팅 뒤 검증할 수 없는 과도한 시간 간격 | 30일 초과 시 보류 |

시간·정확도 검사값은 이 앱의 보수적인 개발 초기값입니다. **Pleos의 공식 권장 반경·위치 갱신 주기·오차 보장이 아닙니다.** SDK 어댑터는 별도로 더 엄격한 위치 유효 시간(현재 15초)과 미래 시각 검사(현재 1초)를 적용하므로, 정책의 30초가 모든 표본에 그대로 보장되는 것은 아닙니다. 실제 기준은 [SDK 연동 경계](pleos-sdk-integration.md)와 코드를 함께 확인합니다.

위치 없음, 새 갱신 아님, 잘못된 시각, 오래됨, 정확도 없음, 부정확함, 범위 밖을 서로 다른 사유로 처리합니다. `getLastKnownLocation()`의 과거 좌표를 단독 인증에 쓰지 않습니다.

**현재 Fused `LocationData.confidence`를 미터 오차로 해석할 공식 근거가 없습니다.** 어댑터는 원시 confidence를 진단에만 두고 `accuracyMeters=null`을 전달합니다. 따라서 콜백 좌표가 도착하더라도 정확도 조건이 확인되기 전에는 LIVE 관광 인증을 보류합니다. 임의 정확도·관광 완료를 만들어 통과시키지 않습니다. SDK 초기화와 실제 표본 수신, 위치 인증은 각각 다른 확인 항목입니다.

## 시간 계산과 한계

`TourClock`은 wall 시각, 단조 시각, OS 부팅 ID를 저장합니다. 같은 부팅에서는 두 경과 시간의 차이를 검사하고 작은 시각 보정으로 15분 전에 해금되지 않도록 더 짧은 경과 시간을 사용합니다. 역행이나 큰 불일치는 보류합니다. 프로세스만 재시작한 것은 새 부팅으로 취급하지 않습니다.

OS가 실제로 재부팅됐다면 영구 저장한 wall 시각 차이를 사용하며 음수·비정상적으로 큰 간격을 보류합니다. 30일 검사는 시계 이상을 살피는 개발용 휴리스틱이며 관광 제한 시간이나 SDK 규칙이 아닙니다. 외부 시간 서버가 없는 로컬 앱이므로 **시스템 시각의 고의 조작을 완벽하게 막지는 못합니다.** 앱이 자동 실행되거나 시동 신호를 타이머로 사용하는 것으로 설명하지 않습니다.

## 두 DataStore의 경계

| 저장소 | 내용·갱신 |
| --- | --- |
| `files/datastore/game-session.json` | 기존 단일 게임 세션, 방문·퍼즐·오답·힌트·정답 공개·단서 보상. 게임 결과는 기존 원자 스냅샷으로 저장합니다. |
| `files/datastore/tour-state.json` | `sessionId + checkpointId + mode`별 최초 관광 시작 시각과 MOCK debug 우회 표시. 하나의 별도 Typed DataStore 인스턴스가 관리합니다. |

관광 시작 저장 성공 후에만 화면에 기록을 공개합니다. 저장 실패 시 완료로 간주하지 않고 재시도 전 변경을 막습니다. 관광 시작과 게임 방문은 두 저장소의 개별 명령이며, 하나의 저장 성공이 다른 원장의 퍼즐 완료·단서 지급을 대신하지 않습니다.

새 게임은 새 session ID를 만들지만 과거 관광 시작 기록을 자동 삭제하지 않습니다. MOCK/LIVE 키는 분리하고, 새 세션이 이전 기록을 재사용하지 않습니다. 원시 위치·음성·현재 주차·UX 상태는 관광 저장소에 넣지 않습니다. 앱 재실행 후 시작 기록만 복원하고 현재 상태는 다시 확인합니다.

기존 게임 schema는 `1`을 유지하며 과거 JSON에 없는 `sourceMode`는 `MOCK` 기본값으로 복원합니다. 이를 LIVE 증거로 재분류하지 않습니다. 손상 관광 JSON·지원하지 않는 버전은 자동 초기화하지 않고 원본을 보존합니다. 관광 저장소의 오류 때문에 기존 게임 원장을 비우거나 덮어쓰지 않습니다.

## SDK·음성·검증

실제 API·권한·버전·SDK Manifest의 INTERNET 선언은 [Pleos SDK 연동 경계](pleos-sdk-integration.md)에 기록했습니다. 위치는 FusedLocation, 목적지 요청은 NaviHelper, 선택 보조 읽기는 Vehicle, 음성은 ON_DEVICE TTS/STT에 연결했습니다. 실제 가청 출력·음성 인식·경로 성공과 차량별 지원은 별도 검증 대상입니다.

음성 인식은 후보 입력만 만듭니다. 숫자형은 선행 0과 한국어 각 자리 발음을 보존하고, 순서형은 지정 방향 토큰을 원래 순서대로 해석합니다. 알 수 없는 말·부호·소수점·길이 오류·상태 조합형은 임의로 추정하지 않습니다. 사용자가 **이 답안으로 제출**을 누를 때 현재 세션·퍼즐·관광·안전 상태를 다시 확인합니다. 인식 결과만으로 제출하거나 해결하지 않습니다.

정책·직렬 처리·실제 DataStore·UI·음성 파서의 실행 명령, 최종 통과·실패·미실행 항목, 기기 관측과 APK 해시는 [검증 기록](verification.md)을 따릅니다. 초기 SDK 컴파일 결과와 후속 수정 뒤의 재검증을 구분하며, Mock 테스트 통과를 실제 Fused 위치 인증·길 안내 완료·가청 음성 출력·실차 성공으로 해석하지 않습니다.

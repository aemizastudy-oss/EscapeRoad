# 관광 시작과 복귀 정책

2026-11-15 사용자 후속 결정. **복귀 시 목적지 위치 확인만 제거하며, 현재 정책의 구현·빌드·기기 검증 결과는 [검증 로그](verification-log.md)에 구분해 기록한다.** 단위 203개·MOCK 기기 회귀 2개·Debug/Release/기기 테스트 APK 빌드를 확인했다. 실제 LIVE SDK 최초 도착과 실차 주행은 이번 검증에 포함하지 않았다.

이 정책은 이전 [SDK 요구 원문](ROAD_ESCAPE_sdk.md), [SDK 연결 기록](sdk-ui-integration.md), 검증 로그의 ‘관광 후 위치 재인증’ 또는 ‘확인된 오래된 위치만 재사용’ 설명보다 우선한다. 원문과 과거 검증 이력은 당시 근거로 보존한다.

## 단계별 조건

| 단계 | 위치 조건 | 계속 확인하는 조건 |
| --- | --- | --- |
| 최초 도착·관광 시작 | 현재 목적지의 유효한 최신 위치·정확도·반경 확인. 현재 반경 기본값은 500m다. | P·실제 정지·차량 이용 허용(CarUx)·앱 foreground·정상 시계 |
| 관광 시간 계산 | 거리·위치 수신 여부로 시간을 멈추거나 초기화하지 않는다. | 저장한 실제 시작 시각과 정상 시계로 경과 시간 계산 |
| 복귀·문제 열기·답안 제출 | 위치·정확도·최신성·목적지 반경을 요구하지 않는다. | 현재 여행 모드·챕터에 맞는 관광 시작 기록, 최소 15분, 정상 시계, P·실제 정지·CarUx·앱 foreground 및 기존 단계·저장·정답 판정 조건 |
| 다음 장소 관광 시작 | 새 장소의 위치 조건을 다시 확인한다. | 해당 장소의 새 시작 기록과 기존 안전 조건 |

관광 시작을 누르면 실제 시작 시각을 저장한다. 목적지에서 출발하거나 반경 밖으로 이동해도, 관광 시작 후의 경과 시간은 계속 포함된다. 따라서 ‘관광 시작 후 15분’은 목적지 반경 안에서 연속 15분 머물렀다는 위치 증명이 아니다.

앱을 닫거나 재실행해도 저장한 시작 기록과 경과 시간을 유지한다. 복귀 시 GPS가 없거나 오래됐거나 정확도를 확인할 수 없어도 같은 여행 모드·챕터의 유효한 시작 기록과 시간·안전 조건을 충족하면 진행할 수 있다. 이전 챕터나 다른 모드의 시작 기록으로는 현재 문제를 열지 않는다. 역행·의심스러운 시계 변경, 시작 기록 누락·불일치는 계속 보류한다.

## 복귀 조작

사용자는 **차로 돌아왔어요** 버튼으로 복귀를 요청한다. 조건이 맞으면 버튼이 활성화되고, 누른 뒤 다시 시간·기록·안전 조건을 확인하여 문제 화면으로 이동한다. 15분 경과 자체로 다음 화면을 자동으로 열거나, 문 열림·좌석 점유·시동 신호로 사람의 재탑승을 감지하는 기능은 추가하지 않는다.

문제 입력과 정답 **제출**에도 같은 복귀 허용 조건과 기존 차량 SDK 표본·연결 세대·명시 제출 검사를 적용한다. 위치 검사 제거가 주행 중 입력이나 실제 SDK 미수신을 허용하는 것은 아니다. 기존 단서·재료·정답·중복 지급 방지·저장 형식은 별도 조건으로 유지한다.

## 실제 SDK와 검증 세션

이번 변경은 최초 위치 인증을 고치거나 생략하지 않는다. 현재 Pleos FusedLocation의 미터 정확도 계약을 확인하지 못해 `accuracyMeters=null`로 처리하므로 일반 LIVE의 최초 도착·관광 시작은 계속 보류될 수 있다. 저장된 관광을 마친 뒤의 위치 재확인 제거와 최초 시작의 위치 문제를 구분한다.

[격리 LIVE SDK 검증 세션](live-sdk-console-test.md)은 debug 전용 UUID 저장소를 사용하며 최초 위치 조건과 15분 대기를 제외한다. 이 예외는 일반 LIVE의 최소 15분 조건과 구분한다. Release에서는 해당 검증 세션이 활성화되지 않는다.

## 검증과 다시 실행

현재 변경의 단위·빌드·기기 확인 여부는 [검증 로그](verification-log.md)의 최신 항목을 따른다. 문서 작성만으로 실행 성공을 표시하지 않는다. Android Studio에서는 최신 코드를 빌드하고 `app`을 Run해야 변경이 기기에 반영된다. Ubuntu에서는 프로젝트의 Gradle 안내에 따라 테스트·재빌드한 APK로 확인한다.

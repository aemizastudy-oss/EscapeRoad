# Escape Road 시안과 앱 화면 대응

기준일: 2026-11-13. [사용자 제공 PDF](<Escape Road 화면 디자인.pdf>) 27쪽을 참고해 기존 Android 앱을 네이티브 Compose 화면으로 재구성했습니다. 2026-11-13에는 배경·질감·로고·장식 그림을 PDF에서 직접 잘라낸 PNG로 교체한 뒤, 별도 요청에 따라 수원 5챕터 관광 설정과 SDK 상태 화면을 추가했습니다. PDF 원본과 사용자 로고 파일은 보존하며 커밋·업로드 완료를 뜻하지 않습니다.

시안의 화면 구도와 분위기를 반영하는 작업입니다. PDF의 사건 스토리·차량 조작·추가 퍼즐을 모두 제품 요구사항으로 바꾼 것은 아닙니다. 수원 관광 흐름은 후속 [SDK 요구사항](ROAD_ESCAPE_sdk.md)을 따르며, 실제 관광 문제와 줄거리는 제작 전입니다. 현재 구현된 동작과 준비 중인 요소를 아래에서 구분합니다. 변경별 빌드·테스트·기기 시연 결과는 [검증 기록](verification.md)에 별도로 남깁니다.

## 공통 테마

버건디 다마스크 바탕, 금색 이중 테두리, 양피지 카드, 명조 본문, 필기체 영문 제목과 각진 버튼을 공통 구성으로 사용합니다. **바탕·종이 질감과 로고·봉투·등대·자물쇠·나침반 등의 장식은 PDF에서 잘라낸 PNG를 실제로 표시합니다.** 경로 도식, 테두리, 동적 텍스트와 입력 버튼의 위치·크기는 네이티브 Compose로 유지합니다. PDF의 정적인 게임 화면 전체를 그대로 표시하는 방식은 아닙니다.

2026-11-12 최초 UI 개편에서는 Canvas와 그라데이션으로 질감·그림을 재구성했습니다. 이 구현 이력과 당시 검증 결과는 보존하며, 2026-11-13 PNG 교체 이후의 화면·검증 결과와 구분합니다.

| 용도 | 코드 색상 |
| --- | --- |
| 버건디 / 어두운 패널 | `#3B0D13` / `#23080C` |
| 금색 / 보조 글자 | `#C8A05C` / `#BDA988` |
| 크림 양피지 / 종이 위 글자 | `#EFE5CC` / `#382A1A` |
| 봉인·강조색 | `#962F37` |

글꼴은 원본을 수정하지 않은 나눔명조 Regular를 앱에 포함해 사용하고, 영문 장식 제목은 Android `Cursive`를 사용합니다. Pleos의 시스템 `serif`가 고딕으로 표시되는 것을 실제 화면에서 확인해 명조를 번들로 제공했습니다. PDF의 본문은 이미지와 OCR 텍스트여서 원래 글꼴을 복원한 것은 아닙니다. 출처·OFL 고지는 [글꼴 고지](third-party-notices.md)에 기록했습니다. 넓은 화면은 편지·진행도와 조작부를 나란히 두고, 좁은 화면은 세로 배치와 스크롤을 사용합니다. 주요 조작 영역은 기존 개발 기준인 최소 56dp를 유지합니다.

## PDF PNG의 출처와 표시 방식

| 항목 | 위치·처리 |
| --- | --- |
| 앱 자산 | `app/src/main/res/drawable-nodpi/pdf_*.png` |
| 추출 스크립트 | [tools/extract_pdf_assets.py](../tools/extract_pdf_assets.py) |
| 출처·영역 명세 | [docs/pdf-assets.json](pdf-assets.json) |
| 원본 자료 | 사용자 PDF 27쪽에 포함된 합성 JPEG의 선택 영역 |
| 가공 | 영역 잘라내기와 일부 배경의 알파 처리 |

이 PNG는 완성된 PDF 화면의 픽셀에서 추출한 자료입니다. 봉투·자물쇠 등의 독립된 원본 레이어, 원본 벡터나 원래 글꼴을 얻은 것으로 설명하지 않습니다. 투명 배경은 원본 색·명도를 기준으로 복원하므로 일부 경계에는 합성 JPEG의 배경색이 남을 수 있습니다. PDF와 사용자 로고 원본은 수정하지 않습니다.

`caseTexture()`는 `ImageBitmap.imageResource`로 읽은 배경·양피지를 `drawWithCache`와 `drawImage`로 그립니다. 화면 영역에 맞춰 중앙을 잘라 표시하고 `clipRect`로 경계를 제한하며, 배경 그림이 카드의 측정 크기를 바꾸지 않도록 합니다. `CaseArtwork`와 로비 로고는 `Image`와 `ContentScale.Fit`으로 비율을 유지해 표시하며, 자물쇠의 장식 PNG 위에 실제 숫자·방향·채널·레벨 입력을 네이티브 컴포넌트로 겹칩니다. `drawable-nodpi`는 Android 리소스 밀도에 따른 비트맵 자동 확대를 피하기 위한 구성입니다. 화면 크기와 밀도가 달라졌을 때의 자르기·비율·터치 위치는 별도의 화면 검증 대상입니다.

기념카드의 화면 삽화와 PNG 출력에도 PDF의 봉투·종이 자산을 사용합니다. 제목·해결 수·건너뜀·힌트·정답 공개 수·날짜는 실제 완료 스냅샷과 발급 시점의 값으로 그립니다. PDF에 인쇄된 예시 정답·진행도·완료 수치를 실제 게임 기록으로 사용하지 않습니다.

현재 추출 자산은 14개, 합계 1,758,874바이트입니다. 원본 PDF와 스크립트, 각 PNG의 SHA-256·출력 크기·원본 영역을 명세와 대조했고 별도 폴더로 재추출한 14개 결과의 해시 일치도 확인했습니다. 이는 자산 추출의 재현 확인이며 화면 표시나 실제 기념카드 파일 저장의 성공과는 구분합니다.

## 추가한 수원 관광 화면

PDF 대응 화면 21개에 아래 경로 2개를 추가해 현재 `NavHost`는 23개 경로입니다. 관광 진행 패널과 음성 컨트롤은 기존 경로에 포함되며 별도 화면 경로로 세지 않습니다.

| 경로·화면 | 진입과 표시 | 동작·제약 |
| --- | --- | --- |
| `tour-setup` · `TourSetupScreen` | 로비의 **수원 관광 코스 · 5챕터**, 더보기의 같은 메뉴 | 화성행궁 → 화홍문 → 만석공원·만석거 → 수원광교박물관 → 광교호수공원 순서와 각 15분 규칙을 안내합니다. LIVE와 debug 전용 MOCK 시작을 명시적으로 선택하며, 기존 세션이 있으면 새 게임 확인을 거칩니다. |
| `sdk-status` · `SdkStatusScreen` | 로비의 **SDK 연결 상태**, 더보기의 같은 메뉴 | 위치·길 안내·주차/주행 제한·차량 상태·TTS·STT 6개 기능의 준비·대기·미지원·권한·오류 상태를 짧은 한국어로 표시합니다. 권한 확인과 돌아가기를 제공하며 원시 SDK 오류·좌표·현재 거리는 표시하지 않습니다. |

설정 화면은 공통 반경 500m가 임시값이고 지정 주차장이 없음을 안내합니다. 만석공원과 광교호수공원의 실제 방문 구역·최종 인증 중심점은 미확정입니다. 공개 관광지 대표점과 합법적인 주차 접근성을 현장 검증한 결과를 혼동하지 않습니다.

`checkpoints` 상단의 `TourProgressPanel`은 현재 챕터와 인증 대기 이유를 표시합니다. 상세 시작 기록·남은 관광 시간과 **관광 시작 / 복귀 위치 재확인**은 foreground·P·정지·CarUx 허용 등 안전 조건이 확인될 때 표시합니다. 최초 시작 시각은 별도 저장하며 재확인으로 다시 시작하지 않습니다. 패널 높이는 최대 360dp와 스크롤을 사용하고 아래에는 기존 경유지 목록을 유지합니다. 실제 모드는 길 안내 요청을, debug MOCK은 범위 안/밖 위치와 명시적인 15분 경과 시연을 제공합니다. 시연 버튼은 실제 방문·15분 관광의 증거가 아닙니다.

LIVE 퍼즐에는 관광·안전 게이트가 열렸을 때 **현재 문제 읽기**, **답안 음성 입력**, **음성 중지**를 표시합니다. 인식 결과는 후보 답안으로 보여 주고 **이 답안으로 제출**을 눌러야 처리합니다. 상태 조합형 등 지원하지 않는 형식을 추정하거나 자동 제출하지 않습니다. 실제 가청 출력·음성 인식·길 안내 성공은 구현 여부와 별도 검증합니다.

현재 Pleos 위치 confidence를 미터 정확도로 바꿀 공식 근거가 없어 LIVE 위치 인증을 보류하며 SDK 화면에도 이를 명시합니다. 연결 준비만으로 도착·관광 완료를 만들지 않습니다. 위치 만료·범위 밖·안전 상태 상실 시 현재 퍼즐과 변경 동작을 막고, 재진입 시 새 위치·안전 관측을 요구합니다. 자세한 시간·위치·SDK 경계는 [관광 흐름](tour-flow.md)과 [SDK 연동 경계](pleos-sdk-integration.md)를 따릅니다.

## 유지한 게임·안전 규칙

기존 `demo_package`의 가상 경유지 3개·자물쇠 3종과 정답(숫자 `0427`, 순서 `UP → RIGHT → DOWN → LEFT`, 상태 조합 `channel=3`, `level=2`)을 유지합니다. 새 `suwon_tour_preview`는 별도 JSON의 5챕터·임시 연동 문제를 사용합니다. 기존 사건 선택은 기존 테스트를, 수원 설정은 관광 패키지를 명시적으로 시작하며 저장된 세션을 자동 전환하지 않습니다. 두 패키지 모두 2단계 힌트·별도 정답 공개·순서 잠금·중복 완료 방지·건너뛰기·단서 보상·단일 게임 세션 저장을 따릅니다.

퍼즐·힌트·단서·수첩·평가·해설·완료 상세는 `canReadContent`의 foreground·P·정지·CarUx·오류·입력 모드 조건을 따릅니다. 관광 퍼즐·힌트와 변경 명령에는 현재 챕터의 시작 기록·15분·새 위치 조건을 추가합니다. 이미 획득한 단서와 메모 등은 안전한 정차 상태에서 볼 수 있으며 다음 챕터의 관광 시간을 기다릴 필요는 없습니다. UNKNOWN을 주차로 간주하지 않고 백그라운드 이후 주차·위치를 다시 확인합니다. 모의 주차·위치·시간 입력은 debug MOCK에만 제공하며 release에는 개발 패널이 없습니다. LIVE는 실제 SDK 어댑터의 미수신·미지원·정확도 미확인을 임의 MOCK으로 대체하지 않습니다.

## 메모·평가·기념카드의 데이터 경계

- **게임 진행 원장:** 기존 Typed DataStore의 `game-session.json`이 단일 세션, 방문·완료·힌트·오답·단서 보상의 기준입니다. 디자인 보조 기능이 이 파일을 변경하지 않습니다.
- **관광 시작 원장:** 별도 Typed DataStore의 `tour-state.json`이 `sessionId + checkpointId + mode`별 최초 시작 시각과 MOCK의 명시적 시간 시연 여부를 보관합니다. 두 저장소는 하나의 트랜잭션이 아니며, 관광 기록 저장 후 방문 저장 전에 중단돼도 **복귀 위치 재확인**으로 방문 저장을 재시도합니다. 원시 위치·주차·UX 상태는 저장하지 않습니다.
- **수첩:** `roadescape-ui` SharedPreferences의 `notebook.<sessionId>.<checkpointId>`에 저장합니다. 경유지별 텍스트는 최대 4,000자이며 **메모 저장**을 눌러야 영구 저장됩니다. 확인 후 현재 페이지를 지우며 다른 메모나 진행 원장은 바꾸지 않습니다.
- **평가:** 같은 SharedPreferences의 `rating.<sessionId>`에 세 항목의 1~5 선택과 최대 400자 후기를 **평가 저장**으로 기록합니다. 서버 전송은 없습니다.
- **세션 분리:** 새 게임의 새 `sessionId`에는 이전 메모·평가를 섞지 않습니다. 이전 세션의 보조 데이터가 남아 있어도 과거 게임을 다시 여는 다중 저장 슬롯이 생긴 것은 아닙니다. 저장하지 않은 편집 내용은 복원 대상으로 보장하지 않습니다.
- **기념카드:** 현재 완료 스냅샷의 제목·세션·해결·건너뜀·힌트·정답 공개 수로 PNG를 출력하도록 구현했습니다. 날짜는 발급 시점의 KST 날짜입니다. `CreateDocument("image/png")` 시스템 파일 선택기 호출을 확인했으나, 현재 Pleos AVD는 해당 선택기가 스텁으로 연결되어 자동 취소되므로 실제 PNG 파일 저장은 미확인입니다. 진행 원장이나 보상에는 영향을 주지 않습니다.

수원 LIVE는 Pleos 위치·안전·선택적 차량 상태 읽기와 길 안내·음성 요청을 연결했지만, 현장 위치 인증이나 실제 출력 성공을 뜻하지 않습니다. 차량 제어·카메라·사진 첨부·다중 게임 세이브는 추가하지 않았습니다. 선택한 파일 제공자가 외부 저장소를 사용하는지는 사용자의 파일 선택 대상에 따르며, 앱 자체의 서버·클라우드 동기화는 추가하지 않았습니다.

## 구현 위치와 검증

공통 테마·PNG 표시 컴포넌트는 `ui/Theme.kt`, `ui/CaseComponents.kt`, 주요 화면은 `ui/CaseScreens.kt`, 퍼즐·도착·힌트는 `ui/CasePuzzleScreens.kt`, 수첩·해설·기념카드·평가·도감은 `ui/CaseExtras.kt`에 있습니다. 관광 설정·진행·음성·SDK 상태는 `ui/TourScreens.kt`, 화면 이동과 확인 대화상자는 `ui/RoadEscapeApp.kt`가 담당합니다. PNG 원본 영역은 추출 스크립트와 자산 명세를 따릅니다.

PDF PNG 교체 시점에는 기존 21개 화면 경로와 게임 도메인·저장소·ViewModel을 유지했습니다. 그 뒤 관광·SDK 확장에서 23개 경로, 별도 관광 원장과 추가 게이트를 연결했습니다. 아래 PNG 검증 결과는 관광 확장 전 이력입니다.

**2026-11-13 관광·SDK 확장 검증 상태:** 첫 기기 실행은 26개 중 25개 통과, 첫 Compose 화면 조회의 `No compose hierarchies found` 오류 1개를 기록했습니다. 해당 시작 대기 helper를 수정했으며, 실행 호스트 종료 문제와 수정 후 전체 재검증 결과는 아직 확인 중입니다. 이 초기 실행을 최종 26개 통과로 표시하지 않습니다. 실제 관광 방문·LIVE 인증·음성·길 안내 성공과 전체 좁은 화면 플레이도 이번 문서의 확인 완료 주장에 포함하지 않습니다. 최종 명령·보고서·APK 해시는 [검증 기록](verification.md)에 따로 남깁니다.

**2026-11-13 PNG 교체 후 검증:** `pdf-assets-verification.log`에서 debug·release 빌드와 Lint가 성공했습니다. JVM `GameCoreTest` 15개와 기기 `GameFlowTest` 6개, 총 21개가 실패·오류·건너뜀 없이 통과했습니다. UI 6개는 자물쇠 완주·초기화 취소·힌트·단서·해설 가림과 수첩·평가의 저장·복원을 포함합니다. 기존 저장소 8개와 VM 순서 검증 4개는 이번에 재실행하지 않았습니다. 최종 Lint는 오류 0개·경고 21개입니다.

PNG 교체 당시 수동 확인에서는 Pleos의 로비·사건 선택·경로·숫자·순서·상태 조합 자물쇠와 힌트, DRIVING 가림, 기념카드 미리보기에서 PNG 표시를 확인했습니다. density 320은 로비 상단의 이미지 비율만 확인했으며 좁은 화면의 전체 플레이 통과로 표시하지 않습니다. 기념카드 미리보기 확인과 실제 PNG 파일 저장의 성공도 구분합니다.

PNG 교체 확인 후 화면 설정을 physical size `2560×1440`, density `160`으로 복원하고 당시 최신 debug 설치를 유지했습니다. PNG 교체 작업 직전에 새로 보관한 원본 진행·기존 백업·프로필 설치 기록 3개를 SHA-256 일치 상태로 복원했으며, 임시 진행과 추가 SharedPreferences가 남지 않은 것도 확인했습니다. 이 복원 기록은 뒤이은 관광·SDK 테스트 후 데이터 복원을 뜻하지 않습니다. 상세 원본 해시와 기기 검증 근거는 [검증 기록](verification.md)을 따릅니다.

**2026-11-12 UI 개편 당시**에는 JVM 15개와 기기 18개, 총 33개가 실패·오류·건너뜀 없이 통과했습니다. 이후 메뉴 활성화와 대화상자 글자색 수정에 대해 debug·release 빌드, JVM 15개와 Lint를 재확인했으며 기기 18개 전체는 다시 실행하지 않았습니다. 당시 최종 Lint는 오류 0개·경고 18개였습니다. 이 수치를 2026-11-13 PNG 교체 이후의 전체 재검증 결과로 재사용하지 않습니다.

2026-11-12에는 넓은 화면과 자물쇠 3종·힌트·메모·평가 저장·DRIVING 가림을 확인했습니다. 로컬 debug 키로 서명한 release 복사본에서도 개발 패널 부재·UNKNOWN과 상세 내용 가림을 확인했습니다. 당시 debug를 재설치하고 원래 저장 데이터를 해시 일치 상태로 복원했습니다. 이 서명은 설치 확인용이며 배포 서명이 아닙니다.

이전 density 320 검증은 로비·힌트 배치만 부분 확인했으며 좁은 화면의 전체 흐름은 완료하지 못했습니다. 기념카드 PNG는 출력 코드와 파일 선택기 호출까지 확인했고 실제 파일 저장은 별도 확인이 필요합니다. Ubuntu 실행도 미실행입니다. 2026-11-13 PNG 교체의 확인 범위, 명령·보고서·APK 해시와 남은 확인 항목은 [최신 검증 기록](verification.md)을 따릅니다.

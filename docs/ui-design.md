# Escape Road 시안과 앱 화면 대응

기준일: 2026-11-13. [사용자 제공 PDF](<Escape Road 화면 디자인.pdf>) 27쪽을 참고해 기존 Android 앱을 네이티브 Compose 화면으로 재구성했습니다. 2026-11-13에는 배경·질감·로고·장식 그림을 PDF에서 직접 잘라낸 PNG로 교체했습니다. PDF 원본과 사용자 로고 파일은 보존하며 커밋·업로드 완료를 뜻하지 않습니다.

시안의 화면 구도와 분위기를 반영하는 작업입니다. PDF에 등장하는 사건 스토리, 실제 장소·차량 조작, 추가 퍼즐과 부가 기능을 모두 확정된 제품 요구사항으로 바꾼 것은 아닙니다. 현재 구현된 동작과 준비 중인 요소를 아래에서 구분합니다. 이번 변경의 빌드·테스트·기기 시연 결과는 [검증 기록](verification.md)에 별도로 남깁니다.

## 공통 테마

버건디 다마스크 바탕, 금색 이중 테두리, 양피지 카드, 명조 본문, 필기체 영문 제목과 각진 버튼을 공통 구성으로 사용합니다. **바탕·종이 질감과 로고·봉투·등대·자물쇠·나침반 등의 장식은 PDF에서 잘라낸 PNG를 실제로 표시합니다.** 경로 도식, 테두리, 동적 텍스트와 입력 버튼의 위치·크기는 네이티브 Compose로 유지합니다. PDF의 정적인 게임 화면 전체를 그대로 표시하는 방식은 아닙니다.

2026-11-12 최초 UI 개편에서는 Canvas와 그라데이션으로 질감·그림을 재구성했습니다. 이 구현 이력과 당시 검증 결과는 보존하며, 2026-11-13 PNG 교체 이후의 화면·검증 결과와 구분합니다.

| 용도 | 코드 색상 |
| --- | --- |
| 버건디 / 어두운 패널 | `#3B0D13` / `#23080C` |
| 금색 / 보조 글자 | `#C8A05C` / `#BDA988` |
| 크림 양피지 / 종이 위 글자 | `#EFE5CC` / `#382A1A` |
| 봉인·강조색 | `#962F37` |

글꼴은 원본을 수정하지 않은 나눔명조 Regular를 앱에 포함해 사용하고, 영문 장식 제목은 Android `Cursive`를 사용합니다. Pleos의 시스템 `serif`가 고딕으로 표시되는 것을 실제 화면에서 확인해 명조를 번들로 제공했습니다. PDF의 본문은 이미지와 OCR 텍스트여서 원래 글꼴을 복원한 것은 아닙니다. 출처·OFL 고지는 [글꼴 고지](third-party-notices.md)에 기록했습니다. 넓은 화면은 편지·진행도와 조작부를 나란히 두고, 좁은 화면은 세로 배치와 스크롤을 사용합니다. 주요 조작 영역은 기존 개발 기준인 최소 56dp를 유지합니다.

## PDF PNG의 출처와 표시 방식

| 항목 | 위치·처리 |
| --- | --- |
| 앱 자산 | `app/src/main/res/drawable-nodpi/pdf_*.png` |
| 추출 스크립트 | [tools/extract_pdf_assets.py](../tools/extract_pdf_assets.py) |
| 출처·영역 명세 | [docs/pdf-assets.json](pdf-assets.json) |
| 원본 자료 | 사용자 PDF 27쪽에 포함된 합성 JPEG의 선택 영역 |
| 가공 | 영역 잘라내기와 일부 배경의 알파 처리 |

이 PNG는 완성된 PDF 화면의 픽셀에서 추출한 자료입니다. 봉투·자물쇠 등의 독립된 원본 레이어, 원본 벡터나 원래 글꼴을 얻은 것으로 설명하지 않습니다. 투명 배경은 원본 색·명도를 기준으로 복원하므로 일부 경계에는 합성 JPEG의 배경색이 남을 수 있습니다. PDF와 사용자 로고 원본은 수정하지 않습니다.

`caseTexture()`는 `ImageBitmap.imageResource`로 읽은 배경·양피지를 `drawWithCache`와 `drawImage`로 그립니다. 화면 영역에 맞춰 중앙을 잘라 표시하고 `clipRect`로 경계를 제한하며, 배경 그림이 카드의 측정 크기를 바꾸지 않도록 합니다. `CaseArtwork`와 로비 로고는 `Image`와 `ContentScale.Fit`으로 비율을 유지해 표시하며, 자물쇠의 장식 PNG 위에 실제 숫자·방향·채널·레벨 입력을 네이티브 컴포넌트로 겹칩니다. `drawable-nodpi`는 Android 리소스 밀도에 따른 비트맵 자동 확대를 피하기 위한 구성입니다. 화면 크기와 밀도가 달라졌을 때의 자르기·비율·터치 위치는 별도의 화면 검증 대상입니다.

기념카드의 화면 삽화와 PNG 출력에도 PDF의 봉투·종이 자산을 사용합니다. 제목·해결 수·건너뜀·힌트·정답 공개 수·날짜는 실제 완료 스냅샷과 발급 시점의 값으로 그립니다. PDF에 인쇄된 예시 정답·진행도·완료 수치를 실제 게임 기록으로 사용하지 않습니다.

현재 추출 자산은 14개, 합계 1,758,874바이트입니다. 원본 PDF와 스크립트, 각 PNG의 SHA-256·출력 크기·원본 영역을 명세와 대조했고 별도 폴더로 재추출한 14개 결과의 해시 일치도 확인했습니다. 이는 자산 추출의 재현 확인이며 화면 표시나 실제 기념카드 파일 저장의 성공과는 구분합니다.

## 유지한 게임·안전 규칙

게임 콘텐츠는 정적 JSON의 테스트 패키지 1개, 순서가 있는 경유지 3개, 자물쇠 3종입니다. 정답은 숫자 `0427`, 순서 `UP → RIGHT → DOWN → LEFT`, 상태 조합 `channel=3`, `level=2`로 유지합니다. 퍼즐마다 힌트 2단계와 별도 정답 해설을 제공하며, 순서 잠금·중복 완료 방지·건너뛰기·단서 보상·단일 세션 저장을 유지합니다.

퍼즐·힌트·단서·수첩·평가·해설·완료 상세는 기존 `canReadContent`와 게임 게이트를 따릅니다. UNKNOWN을 주차로 간주하지 않고, 백그라운드 이후 주차를 다시 확인합니다. 상세 내용을 가려도 debug 개발 패널에서는 주차 상태를 바꿀 수 있습니다. release에는 가짜 제공자와 개발 패널이 없고 외부 상태는 미연동입니다.

## 메모·평가·기념카드의 데이터 경계

- **게임 진행 원장:** 기존 Typed DataStore의 `game-session.json`이 단일 세션, 방문·완료·힌트·오답·단서 보상의 기준입니다. 디자인 보조 기능이 이 파일을 변경하지 않습니다.
- **수첩:** `roadescape-ui` SharedPreferences의 `notebook.<sessionId>.<checkpointId>`에 저장합니다. 경유지별 텍스트는 최대 4,000자이며 **메모 저장**을 눌러야 영구 저장됩니다. 확인 후 현재 페이지를 지우며 다른 메모나 진행 원장은 바꾸지 않습니다.
- **평가:** 같은 SharedPreferences의 `rating.<sessionId>`에 세 항목의 1~5 선택과 최대 400자 후기를 **평가 저장**으로 기록합니다. 서버 전송은 없습니다.
- **세션 분리:** 새 게임의 새 `sessionId`에는 이전 메모·평가를 섞지 않습니다. 이전 세션의 보조 데이터가 남아 있어도 과거 게임을 다시 여는 다중 저장 슬롯이 생긴 것은 아닙니다. 저장하지 않은 편집 내용은 복원 대상으로 보장하지 않습니다.
- **기념카드:** 현재 완료 스냅샷의 제목·세션·해결·건너뜀·힌트·정답 공개 수로 PNG를 출력하도록 구현했습니다. 날짜는 발급 시점의 KST 날짜입니다. `CreateDocument("image/png")` 시스템 파일 선택기 호출을 확인했으나, 현재 Pleos AVD는 해당 선택기가 스텁으로 연결되어 자동 취소되므로 실제 PNG 파일 저장은 미확인입니다. 진행 원장이나 보상에는 영향을 주지 않습니다.

실제 GPS·차량 신호·차량 제어, 음성 내레이션, 카메라, 사진 첨부와 다중 세이브는 연결하지 않았습니다. 선택한 파일 제공자가 외부 저장소를 사용하는지는 사용자의 파일 선택 대상에 따르며, 앱 자체의 서버·클라우드 동기화는 추가하지 않았습니다.

## 구현 위치와 검증

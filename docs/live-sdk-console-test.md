# LIVE 앱과 IDE 콘솔로 차량 문제 확인하기

**2026-11-15 검증 상태: 구현 완료 / Debug·Release 빌드 확인 / Pleos 에뮬레이터 UI 시연 확인.** LIVE로 5개 장소·23개 자물쇠·진 엔딩을 완료하고 재설치·재개를 확인했다. 위치 인증과 실제 관광 15분 경과는 제외했다. 상세 결과와 제한은 [검증 로그](verification-log.md#2026-11-15--위치관광-대기를-제외한-live-sdk-전체-풀이)에 기록한다.

이 기능은 사용자 승인에 따라 **위치 인증과 관광 15분 대기만 제외**하고, 실제 앱 화면에서 Pleos SDK 차량 입력을 확인하기 위한 debug 전용 세션이다. MOCK 관광이나 하이브리드 모드로 전환하지 않는다. 이 세션의 진행 기록은 실제 방문·관광 인증 기록이 아니다.

## 적용 범위

| 항목 | 검증 세션 동작 |
| --- | --- |
| 입력 모드 | LIVE로 시작하며 모드 변경을 막는다. |
| 차량 답안 | 실제 SDK의 방향지시등·창문·독서등 등 지원 신호를 읽는다. 화면 시연 값으로 대체하지 않는다. |
| 안전 조건 | 실제 P·정지·CarUx 이용 허용·앱 foreground를 모두 확인한다. 하나라도 충족하지 않으면 상세 화면과 입력을 차단한다. |
| 위치 | 좌표 설정·현재 위치·정확도·최신성·관광지 반경 등 위치 조건을 제외한다. 가짜 위치 표본을 만들지 않는다. |
| 관광 대기 | 관광 시작은 화면에서 진행하고 실제 시작 시각을 저장한다. 이후 15분 대기 기준만 제외한다. 시계를 변경하거나 시작 시각을 과거로 만들지 않는다. |
| 나머지 검사 | 모드 일치, 관광 시작 기록·챕터·세션, 시계 오류, 차량 표본 최신성·연결 세대, 명시 제출과 중복 지급 방지를 유지한다. |
| 보고서 사진 | 테스트 세션에서는 사진 저장 버튼을 비활성화하고 제외 조건을 안내한다. |
| Release | 검증 세션을 활성화하지 않는다. 같은 Intent extra를 보내도 기존 저장소와 위치·관광 정책을 사용한다. |

SDK의 `READY`는 연결 준비 상태다. 실제 차량 값 수신, 관광 인증, 길 안내 완료, 가청 음성 출력은 각각 별도로 확인한다. 보통 LIVE 실행에서는 Fused 위치의 미터 정확도 계약이 미확정이므로 최초 도착 인증이 보류될 수 있다. 검증 세션은 이 위치 조건을 제외하며 정확도 계약을 확정하지 않는다.

## 검증 세션 시작

1. 최신 debug APK를 준비한다. 기기·Android 사용자 번호를 확인하고 원본 앱의 여행 파일과 환경 설정을 로컬에 백업한다. 에뮬레이터 삭제나 앱 데이터 초기화는 사용하지 않는다.
2. IDE에서 Pleos Virtual Console을 열고 DDS 연결, 실제 P와 속도 0을 확인한다. 콘솔이 실제로 보이는 상태에서 UI를 조작한다.
3. 기존 앱 프로세스를 종료한 뒤 새 UUID를 붙여 실행한다. 아래는 `emulator-5554`, Android 사용자 `10`인 Windows PowerShell 예시다. `adb`가 PATH에 없으면 Android SDK의 `platform-tools/adb.exe` 경로로 실행한다.

```powershell
$liveSdkSessionId = [guid]::NewGuid().ToString()
adb -s emulator-5554 shell am force-stop --user 10 com.team.carescape
adb -s emulator-5554 shell am start --user 10 -n com.team.carescape/.MainActivity --es com.team.carescape.LIVE_SDK_TEST_SESSION $liveSdkSessionId
```

4. 앱 오른쪽 위에 **LIVE SDK 테스트 / 위치·15분 제외 · 테스트 기록** 안내가 있는지 확인한다. UUID가 없거나 올바른 UUID 형식이 아니면 검증 세션은 활성화되지 않는다. 각 검증 실행에는 새 UUID를 사용한다.
5. **실제 SDK · 연결 상태**를 열어 정상 Android 권한 절차로 필요한 권한을 허용하고 P·정지·CarUx 및 필요한 차량 기능의 상태를 확인한다. 앱이 다른 display에 열렸다면 실제 녹화·조작 대상 화면에 앱이 보이는지도 확인한다.

유효한 세션은 MainActivity의 최초 ViewModel 생성 전에 선택된다. ViewModel은 세션과 저장소를 고정해서 사용한다. 앱을 켠 채 전역 설정만 바꾸거나 기존 Activity를 재사용하는 방식으로 검증 모드를 전환하지 않는다.

## 보이는 화면으로 진행하기

1. 앱에서 **사건 고르기 → 이 사건을 맡겠습니다 → 시간 이동 시작**으로 진행한다. 프롤로그의 다음 버튼 또는 원래 제공되는 장면 건너뛰기 버튼으로 사건을 시작한다.
2. 경로 화면의 **다음 장소 길 안내 요청**을 누른다. 위치 조건을 제외한 세션이므로 안전 조건을 충족하면 도착 단계로 진행할 수 있다. 이는 실제 관광지 도착을 확인했다는 뜻이 아니다.
3. 도착 장면을 확인하고 **관광 시작 → 차로 돌아왔어요**로 진행한다. 15분을 실제로 기다린 결과로 기록하지 않는다. 검증 세션에서 관광 대기 안내가 완료 상태로 보여도 상단의 제외 조건이 적용된다.
4. 탐색 화면의 물건과 자물쇠를 실제 UI로 열고, 문제에 필요한 차량 입력은 **IDE 콘솔의 보이는 버튼·스위치·슬라이더**로 조작한다. REST 제어 요청이나 SDK callback 주입, 가짜 안전·위치 값, 저장 파일 수정으로 진행시키지 않는다.
5. 앱에 수신된 상태나 입력 순서를 확인한 뒤 **제출**을 누른다. 차량 신호가 바뀐 것만으로 정답 처리·단서 지급이 되어서는 안 된다. 오답과 정답의 화면 반응, 저장 및 재개 여부는 별도 항목으로 기록한다.

방향지시등을 반복 입력할 때는 Off로 되돌린 뒤 다시 켠다. 창문은 완전히 닫힌 값 0에서 양수로 바뀌는 입력을 읽으며, 계속 열린 상태의 위치 변화는 추가 입력으로 세지 않는다. 콘솔의 % 표시와 SDK의 창문 원시 위치 숫자를 같은 단위로 가정하지 않는다. 봉화는 기본 불씨 1개에 현재 켜진 독서등 수를 더해 왼쪽부터 표시하며, 봉화 4개의 답에는 독서등 3개가 필요하다. 자세한 입력 계약은 [차량 문제 SDK](vehicle-puzzle-sdk.md)를 따른다.

안전 차단도 실제 콘솔 UI로 확인한다. D 상태에서 앱의 안전 안내와 입력 차단을 관찰한 뒤 P·속도 0으로 복귀한다. SDK에서 CarUx 이용 허용까지 다시 확인된 후 화면이 회복되는지 확인한다. P 선택만으로 모든 안전 조건이 충족됐다고 판단하지 않는다.

검증 세션에서는 원본 여행의 `DriveService.watch`와 `DemoArrival.watch`를 시작하지 않고, 원본 여행 서비스를 호출하는 **출발하기** 버튼을 숨긴다. 실행 전 force-stop은 이미 동작하던 앱 서비스가 이 확인에 섞이지 않도록 하기 위한 절차다.

## 저장 격리와 결과 기록

검증 진행은 앱의 비공개 경로에 저장된다.

```text
files/sdk-live-tests/<검증 UUID>/trip-progress.json
```

원본 `files/datastore/trip-progress.json`의 LIVE/MOCK 여행·완료 기록·archive·schema는 이 세션의 진행 저장에 사용하지 않는다. 격리 파일 안의 모드는 실제 SDK 입력을 뜻하는 LIVE이지만, 위치·시간을 제외한 **검증 기록**이다. 이를 원본 여행으로 복사하거나 실제 관광 인증 결과로 합치지 않는다. Release와 일반 실행은 이 검증 파일을 자동으로 읽지 않는다.

검증 로그에는 다음을 구분해서 남긴다.

- APK·SDK·에뮬레이터 버전, Android 사용자, 검증 UUID, 제외한 위치·15분 조건.
- 보이는 콘솔 UI에서 조작한 값과 실제 앱 SDK 수신·화면 반응의 관측쌍.
- 제출 전후 답안·정오답·단서·저장 상태와 실제 안전 차단·복귀 결과.
- 테스트 전후 원본 여행 파일 비교, 콘솔 조작값 복원, 정상 실행 복귀 여부.

화면·원시 SDK 로그·사용자 백업·격리 진행 파일은 로컬 검증 자료로 보관한다. 현재 문서만으로 빌드·실제 SDK 입력·저장 복원·전체 스토리 완료를 통과했다고 표시하지 않는다.

## 종료하고 기존 정책으로 돌아가기

1. 콘솔에서 바꾼 신호를 시작 전 상태로 되돌리고 실제 P·속도 0을 확인한다.
2. 앱을 force-stop하고 **extra 없이** 새로 실행한다. 원래 Intent를 재사용하는 최근 앱 화면 복귀만으로 검증 세션이 해제됐다고 판단하지 않는다.

```powershell
adb -s emulator-5554 shell am force-stop --user 10 com.team.carescape
adb -s emulator-5554 shell am start --user 10 -n com.team.carescape/.MainActivity
```

3. **LIVE SDK 테스트** 안내가 없어졌는지와 원본 여행 파일이 보존됐는지 확인한다. 일반 debug 실행은 기존 기본 모드인 MOCK으로 시작하므로 실제 LIVE로 확인하려면 로비의 개발 패널에서 **실제 SDK**를 선택한다. Release의 기본 모드는 LIVE다.
4. 일반 LIVE에서는 원래 위치 인증과 최소 15분 관광 정책이 다시 적용된다. 정확도 미확정으로 도착이 보류되는 기존 동작도 유지된다. 검증 세션의 예외를 일반 LIVE의 영구 설정으로 설명하지 않는다.

관련 구현: debug/release의 `ui/LiveTourTestSession.kt`, `MainActivity`, `GameViewModel`, `SdkDevPanel`. 기존 정책 본체인 `TourPolicy`와 원본 저장 검증 규칙은 변경하지 않는다.
